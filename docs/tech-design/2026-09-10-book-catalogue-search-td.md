# Book Catalogue Search and Date Filtering API

## Goal

Extend the existing protected `GET /books` endpoint so callers can search the catalogue by title and author and restrict results to an inclusive publication-date range. Preserve the current response shape and no-parameter behaviour.

Success means a caller can combine text search and either or both date bounds in one request, receives deterministic results, and PostgreSQL can execute the text and date predicates using purpose-built indexes.

## Current State

- `GET /books` in `backend/app/routers/books.py` currently returns every `Book` ordered by `id`; it has no query parameters.
- `books.title` and `books.author` are non-null strings. `books.date` is a non-null integer containing a UTC Unix timestamp in seconds; creation and update accept offset-aware ISO 8601 datetime strings and normalize them to that integer.
- The backend uses FastAPI, SQLAlchemy 2.x async sessions, PostgreSQL 14+, and Alembic. The current migration head is `20260910_0003`.
- Existing API tests use a lightweight fake async session. PostgreSQL-backed schema tests are skipped unless `TEST_DATABASE_URL` or `DATABASE_URL` is configured.
- The checked-in OpenAPI document is generated by `backend/scripts/refresh_openapi.py`.
- The worktree has unrelated untracked root files (`.gitignore`, `LibraryAppHLS.excalidraw`, `docs/product_requirements.md`, and `docs/take_home_assignment.md`). Preserve them.

## Decisions

- Add optional query parameters to `GET /books`:
  - `q`: a non-blank, user-facing text query across both `title` and `author`.
  - `date_from`: an inclusive lower publication-date bound.
  - `date_to`: an inclusive upper publication-date bound.
- Accept `date_from` and `date_to` as offset-aware ISO 8601 datetime strings, using the existing publication-date parsing rules, then compare their UTC Unix-second values with `books.date`. This keeps filtering consistent with the existing write contract rather than introducing a second date representation.
- Reject blank `q`, timezone-naive date bounds, malformed date strings, and `date_from > date_to` with FastAPI/Pydantic validation (`422`). Omitted parameters impose no filter.
- Use PostgreSQL full-text search for `q`, not `ILIKE`. Construct a `tsvector` expression from title and author using the `simple` text-search configuration, and parse request text with `websearch_to_tsquery('simple', q)`. `simple` provides case-insensitive token matching without English-only stemming, which is safer for author names and multilingual catalogue data.
- Index the exact combined `tsvector` expression with a GIN index. This is PostgreSQL's inverted index for full-text search and supports a query across either title or author without separate text indexes.
- Weight title terms above author terms in the vector and order text-search results by descending `ts_rank_cd`, then `id` ascending. When `q` is absent, retain the current `id`-ascending order. The rank is internal only; do not change `BookResponse`.
- Add a B-tree index on `books.date` for lower-bound, upper-bound, and bounded range predicates. A GIN full-text index is not appropriate for numeric range filtering.
- Do not add `pg_trgm`, `unaccent`, or a stored/generated search-vector column in this slice. `pg_trgm` is appropriate only if requirements later add substring/prefix or typo-tolerant search; `unaccent` requires a confirmed accent-insensitive matching requirement and extension availability. An expression index is smaller in scope than a persisted extra column and is sufficient when the query expression is kept identical.
- Do not add pagination, alternate sort options, ISBN search, facets, autocomplete, fuzzy matching, or frontend changes. Existing authorization remains unchanged.

## Interface

```text
GET /books?q=le%20guin&date_from=1960-01-01T00:00:00Z&date_to=1970-12-31T23:59:59Z
Authorization: Bearer <existing permitted token>
```

- `q` matches title or author terms. Multi-word input follows PostgreSQL web-search syntax and is safe to pass as a user query; quoted phrases and a minus prefix retain their PostgreSQL web-search meanings.
- All supplied filters are combined with `AND`. For example, `q` limits the title/author match set first, then both date bounds limit that set.
- `date_from` and `date_to` are inclusive. A request with only one bound remains valid.

## Implementation Steps

1. Add a small query-parameter schema or dependency in `backend/app/schemas/book.py` (or the books router if it remains clearer) that defines `q`, `date_from`, and `date_to`. Reuse the existing ISO-date-to-epoch conversion rather than duplicating parsing logic, and validate bounds only after both values have been normalized.
2. In `backend/app/routers/books.py`, construct the shared PostgreSQL search-vector expression from `Book.title` and `Book.author`, with title weight `A` and author weight `B`. Build the `select(Book)` incrementally for present filters; use `@@ websearch_to_tsquery('simple', q)` for `q`, integer comparisons for bounds, and retain `Book.id` as the deterministic tie-breaker. Apply relevance ordering only when searching.
3. Add a reversible Alembic revision after `20260910_0003`. Its upgrade creates:
   - `ix_books_title_author_search` as a GIN expression index over the exact weighted `tsvector` expression used by the router.
   - `ix_books_date` as a B-tree index on `date`.
   Its downgrade drops precisely those indexes. Use explicit `CREATE INDEX` SQL where Alembic/SQLAlchemy expression-index rendering would obscure the required immutable expression; use the same expression text in production queries.
4. Keep the ORM model metadata aligned with the migration by declaring the two indexes on `Book` if SQLAlchemy can render the same expression unambiguously. If it cannot, document the migration-owned expression index rather than adding a misleading or divergent model declaration.
5. Add API coverage in `backend/tests/test_books.py` for: title and author matches; case-insensitive matching; no match; each date boundary independently; an inclusive two-sided range; combined text/date filtering; blank/invalid/naive dates; reversed bounds; and unchanged unfiltered ordering. Update the fake session only as far as necessary to model the added select behaviour without reimplementing SQLAlchemy.
6. Add PostgreSQL-backed tests in `backend/tests/test_database.py` that assert both indexes exist and verify query results for text and date predicates against seeded records. Where practical, run `EXPLAIN` only as a diagnostic, not an assertion, because the planner may legitimately choose a sequential scan for a tiny test table.
7. Regenerate `docs/openapi.json`, update the `GET /books` documentation in `backend/README.md`, and add filtered examples to `backend/sample_requests/books.txt` if it is the maintained request collection.

- From `backend/`, run `./scripts/test.sh`.
- Repeat with `TEST_DATABASE_URL` set to an isolated PostgreSQL database migrated through the new revision.
- On a disposable database, run `uv run alembic upgrade head`, inspect both index definitions with `pg_indexes`, then downgrade and re-upgrade to confirm migration reversibility.
- Create books whose title, author, and publication timestamps distinguish every search case. Verify `q` matches either textual field, date-only requests respect inclusive epoch boundaries, and combined filters return their intersection.
- Verify malformed and timezone-naive bounds, blank `q`, and reversed ranges return `422`; verify no query parameters return the same full list in ID order as before.
- Start the API, inspect `/docs`, run `uv run python scripts/refresh_openapi.py`, and confirm the checked-in OpenAPI diff exposes the three optional query parameters.

## Risks and Open Questions

- The plan assumes token-based catalogue search is desired. Full-text search does not provide arbitrary substring matches such as `urs` matching `Ursula`, nor does it correct typos. Add `pg_trgm` GIN expression indexes only if those behaviours become requirements.
- `simple` preserves words rather than stemming them. If the catalogue is explicitly English-only and users should match morphological variants (for example, `stories` and `story`), switch both the index and query to the `english` configuration in a separate, deliberate change.
- The existing endpoint is currently admin-only in this worktree. This plan intentionally does not alter authorization; if all authenticated users should search the catalogue, make that access-policy change separately or explicitly fold it into implementation scope.
- No pagination is included, matching current endpoint behaviour. Add a bounded pagination contract before catalogue size makes unbounded results operationally unsafe.

## Handoff Notes

- The GIN index is the requested inverted index: it indexes lexemes from a combined title/author `tsvector`. Keep the vector expression and text-search configuration identical in the migration and router or PostgreSQL cannot use the intended index.
- Use the B-tree `date` index for range filtering; no PostgreSQL extension is needed for it.
- Do not introduce extensions in this slice. `pg_trgm` and `unaccent` carry additional operational requirements and solve search behaviours not requested here.
- Preserve the existing asynchronous SQLAlchemy session pattern and module-level FastAPI dependency convention.
